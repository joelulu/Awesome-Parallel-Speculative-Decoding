## 今日值得更新的工程进展

### SGLang PR #39254：修复 pack-quantized DFlash2 draft 的 `fc` 权重静默漏载

- **问题**：使用 `compressed-tensors` 的 pack-quantized DFlash2 checkpoint 会把 target-context projection `fc` 保存为 `fc.weight_packed / fc.weight_scale / fc.weight_shape`；此前 `DFlash2DraftModel` 却把 `fc` 构造成普通 `torch.nn.Linear`，loader 无法解析这些 packed tensors，并会静默跳过，使 `fc` 保持随机初始化。
- **为什么重要**：服务仍能启动，target verification 也保证最终输出正确，因此普通 correctness test 很难发现；但 drafter proposal quality 会崩溃，acceptance 接近只剩 bonus token 的状态。这正是 9 月 14 日简报记录的 issue #39087 的直接修复进展。
- **修复**：在存在 quantization config 时，用 SGLang quantization-aware linear 构造 `fc`，保留 dense/BF16 path，并增加 packed weight loading 与 shape validation 的 CPU regression tests。
- **结果**：PR 报告修复后的 W4A16 draft mean accept length 3.23，对照 BF16 为 3.25；mean acceptance rate 0.32，对照 0.31，说明量化 drafter 的 speculative acceptance 已恢复到 BF16 reference 水平。
- **状态**：截至本期检查，PR 仍为 open，属于重要修复进展而不是已合并发布。

来源：https://github.com/sgl-project/sglang/pull/39254

## 研究提示

这次修复再次说明：**speculative decoding 的 lossless correctness 会掩盖 drafter health regression**。后续 DFlash / DFlash2 benchmark 建议把 `accept length / acceptance rate / bonus-token-only ratio` 作为部署级健康指标，并对量化 checkpoint 增加权重完整性检查；只看“服务能启动、输出正确、tok/s”不足以定位这类静默退化。
