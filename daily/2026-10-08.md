| 2026-09-29 | [DScale: Scaling Block-Diffusion Speculative Decoding with Adaptive Verification](https://arxiv.org/abs/2609.37532) · [论文全文](https://arxiv.org/html/2609.37532v1) | 不改 DFlash drafter，在高并发下将各请求的验证前缀装入一半原生验证槽位；单张 A100、Qwen3-4B/8B、并发 8–32 上相对 DFlash 报告 48.8%/43.9% 几何平均吞吐提升。 | 固定宽度验证造成大量 padding；请求接受长度不同，简单截短会浪费可接受 token；动态边界又会与固定形状 CUDA Graph 和 CPU 切片产生冲突。 | 区分 prefill/verify 的 path-aware tiles；用每个 target–drafter 对训练的 112K 参数预测器估计接受前缀，再由 dynamic verify-length（DVL）在半预算内跨请求重分配；固定地址工作区将边界通过验证与接受流程，复用 CUDA Graph。 | **解决什么：** 直接减少 DFlash 高并发验证计算和 padding。**为什么 DFlash 需要：** 论文分析中 Qwen3-8B、并发 16 的 DFlash GPU kernel 时间 83.3% 在 target verify；草稿质量提升无法消除这项系统瓶颈。**核心方法：** 预测接受长度、共享预算分配、按路径选择 tile、GPU 固定地址动态打包。**路线价值：** 值得加入 Verification Cost 长期路线；论文直接复用 DFlash drafter，但结果只覆盖其报告的 A100/TP1 与模型、负载，不应外推为普遍收益。尚未核实作者官方代码链接。 |
| 2026-08-31（v2：2026-09-29） | [GLANCE: Vision Is Not Overhead](https://arxiv.org/abs/2609.00355) · [官方代码](https://github.com/js-lee-AI/GLANCE) | 将 DFlash 风格的 block-diffusion head 接到 target 已融合的 VLM 视觉语言状态，一次起草整块并通过一轮 target pass 验证候选树。 | 多模态自回归 drafter 逐 token 成本高；为省成本而压缩或隐藏视觉信息，则在 OCR、图表问答等 grounded 文本上失去关键条件。 | 利用视觉编码已经融合进 target hidden states 的条件，以一次并行 block draft 与 wide prefix-closed tree 验证；论文给出 greedy 输出严格一致的成立条件，并对审计 prompt 验证。 | **解决什么：** VLM 的视觉条件化草拟效率与保真。**为什么 DFlash 需要：** 将其单次 block-diffusion draft 思路扩展到图像条件文本，同时保留 target verifier。**核心方法：** 读取融合视觉语言 hidden states、一次预测 block marginals、构造候选树。**路线价值：** 值得加入多模态/Beyond text 路线；单 RTX A6000、bf16、SGLang 0.5.6、共用 32 候选预算时五任务几何平均较 EAGLE3-VL 仅快 1.3%，grounded 子集约快 11%，captioning 更慢。AR 的最高 3.05×仅在 ChartQA decode-only，不作普遍结论。 |
