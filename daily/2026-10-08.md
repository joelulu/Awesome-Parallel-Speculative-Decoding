## 逐篇核验与路线判断

### DSpine — 2026-09-28

- **解决什么：** 独立位置的预测缺少真实前驱条件；只在骨干输出后做因果校正，无法帮助浅层形成更好的后继表示。
- **为什么 DFlash 需要：** 逐层把前驱预测特征注入后继，在并行 DFlash 骨干内部建立相邻因果依赖。
- **方法核心：** 在每个 draft 层后以门控注入相邻前驱预测特征，使用 block-causal attention；将冻结 LM-head 嵌入映射到 PCA 白化的低维空间，以逐层余弦监督训练浅层预测，并用同一注入算子做末次修正和预计算候选转移。
- **长期路线与边界：** 直接基于 DFlash 骨干，值得纳入块内因果关系与 Draft Quality 长期路线。Qwen3-4B/8B、15 个 proposal、四个数学/代码任务上评测，SGLang 平均吞吐较 DFlash 提高 23.3%；仍有按前驱选择候选的轻量顺序操作，不能称为完全无串行依赖。未核实作者代码。
- **原始来源：** [DSpine](https://arxiv.org/abs/2609.36173) · [正文](https://arxiv.org/html/2609.36173v1)

### DRelay — 2026-10-01

- **解决什么：** 早期 token 选错会截断可接受前缀，即使正确 token 已在 top-k 池、后续预测也可提供辨别证据，单向因果 head 仍无法回看这些信息。
- **为什么 DFlash 需要：** 读取整块候选分布，用实际已选前缀决定 KEEP/REPAIR，在 target 验证前修复早期选错。
- **方法核心：** Global Read 并行读取 top-16 候选和后续预测；Causal Selector 逐位置查询可寻址的已选前缀及严格已验证历史，门控保留或替换候选。联合训练候选支持、修复 gate/rank，以到达概率和后续连续接受价值加权修复 loss。
- **长期路线与边界：** 明确引用并对比 DFlash，值得纳入块内修复与 acceptance-aware Training 路线；不把它宣称为冻结 DFlash 权重的即插即用扩展。Qwen3-4B/8B、八任务、单 H800，SGLang 平均端到端 speedup 相对 DFlash 提高 14.7–16.8%。全局读并行，15 次 causal selection 顺序执行；动机中的 oracle 修复收益不等于部署收益。未核实官方代码。
- **原始来源：** [DRelay](https://arxiv.org/abs/2610.01439) · [正文](https://arxiv.org/html/2610.01439v1)

### UBTree — 2026-09-30

- **解决什么：** 独立候选分布无法给不同前驱下的树分支可靠打分；只训练主路径又削弱候选池多样性。
- **为什么 DFlash 需要：** DFlash 并行提出 unigram 候选，以可查表的 bigram 兼容分数构建更有条件相关性的树。
- **方法核心：** 在预训练 DFlash proposer 上训练 target 嵌入衍生的两套 MLP bigram codebook、深度缩放与 selector；候选对神经打分并行，再用 DARTree 的逐深度搜索和全局剪枝建树。高温 target 轨迹配合 proposer CE 和候选支持集重归一化的 forward-KL 训练。
- **长期路线与边界：** 值得纳入 Candidate Search 与树原生训练路线；直接使用 DFlash proposer，借鉴 DFlash2 selector，并采用 DARTree 搜索。单 H200、batch 1 的 64-node 学术验证与 DFlash 16-token 路径预算不同；SGLang 并发 1/8/16/32 各自调优 B/W 后，相对次优基线报告 7.0–16.3% 吞吐收益。神经评分并行，树搜索仍有顺序操作。未核实官方代码。
- **原始来源：** [UBTree](https://arxiv.org/abs/2609.39972) · [正文](https://arxiv.org/html/2609.39972v1)

### PRESTO — 2026-06-20

- **解决什么：** diffusion 边缘概率缺少路径条件，直接相乘会错误排序候选前缀，并浪费树预算。
- **为什么 DFlash 需要：** 将 diffusion marginals 与轻量前缀条件分数结合，以优先级搜索选取更可能被验证接受的树。
- **方法核心：** 以 log marginal 加权融合前缀条件信号，论文用 trigram；以 best-first 或 beam search 加全局保留分配树节点，适配独立 DFlash drafter 和共享模型自投机。
- **长期路线与边界：** 历史遗漏补收，值得纳入 Candidate Search 长期路线。直接在 DFlash 上扩展树草拟，且不额外训练模型。B200、batch 1、PyTorch/FlexAttention，扫 128/256/512 预算后选最佳吞吐，DFlash 路线约 1.5×增益；不代表同预算或高并发 serving 保证。日期按 arXiv 提交历史 2026-06-20，不能由 2607 编号推断日期。未核实官方代码。
- **原始来源：** [PRESTO](https://arxiv.org/abs/2607.22634) · [正文](https://arxiv.org/html/2607.22634v1)

### SharpDraft — 2026-10-04

- **解决什么：** 长上下文使 softmax 竞争 Key 增多，重要 Key 的 attention mass 被稀释；接受率降低，在线重训又增加延迟和显存。
- **为什么 DFlash 需要：** 按可见 Key 数缩放 DFlash query，无需更新权重即可缓解长生成的 attention mass dilution。
- **方法核心：** 在 Q-normalization 后应用带上限的长度相关 query scale，以参考 Key 数和固定斜率近似 top-k mass 校正；target、验证规则和缓存 K/V 均保持原实现。
- **长期路线与边界：** 直接在 DFlash 上实现与评测，值得纳入 Draft Quality 的长度泛化路线。主要端到端实验为单 RTX 6000 Ada、greedy、Qwen3-4B/8B 与 Llama-3.1-8B；三任务几何平均 AR 相对速度 2.59–3.19×。attention-mass 推导有条件假设，固定斜率近似不保证接受率；100K 多轮实验仅验证 MAL，包含重复续写，不能称为 100K 端到端加速。未核实官方代码。
- **原始来源：** [SharpDraft](https://arxiv.org/abs/2610.05106) · [正文](https://arxiv.org/html/2610.05106v1)

### LongSpark — 2026-09-29

- **解决什么：** DFlash/DSpark 每轮读取完整前缀，长上下文下草拟延迟和独立状态持续增长。
- **为什么 DFlash 需要：** 用固定大小的三种 target 上下文视图，让并行 drafter 成本不再随前缀长度增长。
- **方法核心：** 融合边界 hidden state、原位近期 KV 窗口与可增量更新的全局注意力摘要；并行 backbone 后接 DSpark 式低秩因果修正。
- **长期路线与边界：** 已补齐 arXiv 原文与 PDF，值得纳入 Draft Quality 的固定成本长上下文路线。固定的是 drafter 状态与每轮草拟工作，target KV 仍增长；论文投机配置比 AR 多一张专用 drafter GPU，吞吐不能解释为同 GPU 数收益。
- **原始来源：** [LongSpark](https://arxiv.org/abs/2609.37029) · [正文](https://arxiv.org/html/2609.37029v1) · [官方实现](https://github.com/Hao-Yuan-He/LongSpark)

### Fast-dVLM — 2026-04-08

- **解决什么：** VLM 逐 token 解码难利用硬件并行，先改文本骨干再做视觉对齐又可能破坏预训练多模态能力。
- **为什么 DFlash 需要：** 图像条件文本同样需要低成本并行草拟及因果验证；原文引用 DFlash，但本方法转换 target 本身。
- **方法核心：** 直接转换完整 VLM，以 block-size annealing、causal context attention、auto-truncation masking 与视觉拼接训练；共享权重的 diffusion 模式生成块、AR 模式验证前缀，支持 linear 与 quadratic 自投机和定制 SGLang。
- **长期路线与边界：** 多模态历史补收；原文明确引用 DFlash，但训练会修改整个 VLM，属于共享模型自投机相关路线。值得纳入 Beyond text 长期观察。MMMU-Pro-V 的 self-spec 是 1.98× AR 吞吐；超过 6×另包含 SGLang/FP8，不能视为纯算法增益，也不能宣称与原始未转换 AR 模型精确等价。
- **原始来源：** [Fast-dVLM](https://arxiv.org/abs/2604.06832) · [正文](https://arxiv.org/html/2604.06832v2) · [官方实现](https://github.com/NVlabs/Fast-dLLM/tree/main/fast_dvlm)

### Fast-dDrive — 2026-05-22

- **解决什么：** 完整序列扩散会混淆感知与规划因果顺序；AR 驾驶输出串行慢，固定格式 token 又占用草拟和验证预算。
- **为什么 DFlash 需要：** 驾驶输出中的语义段与模板提供并行草拟的具体边界；该联系是相关范式，不能声称原文直接扩展 DFlash。
- **方法核心：** 基于 Fast-dVLM 保留段间因果、段内双向关系，以分段加权 loss 和噪声训练；Scaffold Spec 自动接受模板 token，仅并行草拟动态值并以因果 AR forward 验证。
- **长期路线与边界：** 多模态/VLA 历史补收；明确扩展 Fast-dVLM，未核实直接引用或继承 DFlash，因此仅经共享自投机路线关联。值得观察结构化多模态解码与预算节省；模板自动接受以固定 schema 为前提。WOD-E2E 的约 12×包含 scaffold 与 SGLang，TPS 包含模板 token，不能泛化为 DFlash 加速或安全性保证。
- **原始来源：** [Fast-dDrive](https://arxiv.org/abs/2605.23163) · [正文](https://arxiv.org/html/2605.23163v2) · [官方实现](https://github.com/NVlabs/Fast-dLLM/tree/main/fast_ddrive)

## 保留本日早先核验记录

[DScale: Scaling Block-Diffusion Speculative Decoding with Adaptive Verification](https://arxiv.org/abs/2609.37532) · [论文全文](https://arxiv.org/html/2609.37532v1)

**解决什么：** 直接减少 DFlash 高并发验证计算和 padding。**为什么 DFlash 需要：** 论文分析中 Qwen3-8B、并发 16 的 DFlash GPU kernel 时间 83.3% 在 target verify；草稿质量提升无法消除这项系统瓶颈。**核心方法：** 预测接受长度、共享预算分配、按路径选择 tile、GPU 固定地址动态打包。**路线价值：** 值得加入 Verification Cost 长期路线；论文直接复用 DFlash drafter，但结果只覆盖其报告的 A100/TP1 与模型、负载，不应外推为普遍收益。尚未核实作者官方代码链接。

[GLANCE: Vision Is Not Overhead](https://arxiv.org/abs/2609.00355) · [官方代码](https://github.com/js-lee-AI/GLANCE)

**解决什么：** VLM 的视觉条件化草拟效率与保真。**为什么 DFlash 需要：** 将其单次 block-diffusion draft 思路扩展到图像条件文本，同时保留 target verifier。**核心方法：** 读取融合视觉语言 hidden states、一次预测 block marginals、构造候选树。**路线价值：** 值得加入多模态/Beyond text 路线；单 RTX A6000、bf16、SGLang 0.5.6、共用 32 候选预算时五任务几何平均较 EAGLE3-VL 仅快 1.3%，grounded 子集约快 11%，captioning 更慢。AR 的最高 3.05×仅在 ChartQA decode-only，不作普遍结论。
