## 工程侧最值得关注的结论

**一、Draft Context 的信息来源正在成为核心竞争点。** SpecForge Q4 Roadmap [#949](https://github.com/sgl-project/SpecForge/issues/949) 记录目前 KV-based 相对 hidden-state-based 实测约 **-2%** 的性能差距，需要更大数据量验证；训练侧 [#969](https://github.com/sgl-project/SpecForge/pull/969)、[#971](https://github.com/sgl-project/SpecForge/pull/971) 正在做 `conditioning_source=hidden|kv` 的统一接口和 Qwen3 Target KV 采集。**目前是开放中的训练 PR，不是已发布推理收益。**

**二、长上下文的目标不是最大化 Acceptance，而是控制 Draft 读取成本。** vLLM [#61261](https://github.com/vllm-project/vllm/pull/61261) 研究只限制 DFlash/DSpark Drafter 的历史窗口；Kimi-K3 DSpark 在 128K+ 长上下文出现 acceptance 崩落，作者提供 32K draft window 的对照。SpecForge [LongSpark RFC #976](https://github.com/sgl-project/SpecForge/issues/976) 则提出边界 hidden + 近期 target KV + 固定大小 summary 的有界输入。两者都适合和已有 LongSpark/FOLD/Frozen Short Drafter 工作一起对照。

**三、工程吞吐瓶颈不仅在 Draft 网络深度。** vLLM [#58984](https://github.com/vllm-project/vllm/pull/58984) 在 DeepSeek-V4.1-Flash / H20 下处理 DP Draft CUDA graph padding，作者报告并发 8 output TPS **+14.31%**，并发 64 仅 **+1.06%**，且 TTFT 有回归点；SGLang [#44752](https://github.com/sgl-project/sglang/pull/44752) 优化 EAGLE/DFlash/DSpark verify sampling 的 fused softmax/argmax；TensorRT-LLM [#20374](https://github.com/NVIDIA/TensorRT-LLM/pull/20374) 探索低 Batch 下 DFlash non-causal Attention 的 decode-row 并行度。对自己的双流/Looped Draft 实验尤其要报告 **GPU time + total wall time**。

**四、实际大模型适配难点在 Hybrid KV/MLA/CP/精度一致性。** DeepSeek-V4 原生 DSpark [SpecForge #981](https://github.com/sgl-project/SpecForge/pull/981) 仍处开发；SGLang [#43265](https://github.com/sgl-project/sglang/pull/43265) 针对 DeepSeek-V4 + CP 的 draft KV Pool 与 OOM 风险；Kimi-K3 [SGLang #43599](https://github.com/sgl-project/sglang/pull/43599) 涉及 MLA/DCP/HiCache 的 Draft KV 还原位置，错误可能降低 Acceptance；vLLM Speculators [#1233](https://github.com/vllm-project/speculators/pull/1233) 修复 DFlash 模型转换时丢失逐层因果配置。**这种转换/Cache 错误会表现得像算法质量下降。**

## 值得追加到现有实验的最小验证

1. **Target hidden 与 KV 双路线对比**：在相同 DFlash/DSpark model depth、数据量、loss、GPU 和训练 token 下，hidden / KV / 混合读取三组；报告单步 draft attention time、preprocessing、接受长度、端到端 tok/s。SpecForge #949 的 -2% 是动机，不能照搬为自己的结论。
2. **长上下文 window × visual KV mask**：选 8K/32K/128K、C1/8/32，保留文本 KV、对视觉 KV 做全遮/Top-K/滑窗，与 `draft_context_window` 和 LongSpark 比较，尤其看视觉信息是否已隐式编码进 hidden。
3. **真实双流并发冲突**：对照 serial/dual-stream 与 fused/overlap，在固定 target/draft 工作量下测 Kernel timeline、SM usage、HBM throughput、draft GPU ms、target GPU ms、wall_ms；验证并发双方是否 compute-bound 竞争。
4. **跨框架模型一致性**：相同 Draft checkpoint 在 Speculators/SpecForge 导出、SGLang/vLLM serving 中检查层级 causal mask、position/RoPE、logit head、acceptance，避免配置转换错误造成假性下降。
